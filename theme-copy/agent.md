# 프로젝트 작업 지침

## 1. 사용자

- 이 서비스는 코딩 초보자가 만드는 모바일 웹 초대장 제작 서비스다.
- 개발 과정을 한국어로 쉽게 설명한다. 전문 용어가 필요하면 뜻과 사용하는 이유를 함께 설명한다.
- 작업은 이해하고 확인할 수 있는 작은 단위로 진행한다. 완료 후 무엇을 바꿨는지, 어떻게 확인했는지, 남은 작업이 무엇인지 알려준다.
- **모르거나 애매한 부분은 반드시 사용자에게 질문한다. 임의로 추측하거나 결정해서 구현하지 않는다.**
- 질문할 때는 어떤 결정이 필요한지와 선택지의 차이를 쉬운 말로 설명한다. 답변이 필요한 부분은 기다리고, 확정된 범위의 독립적인 작업은 진행할 수 있다.
- 서비스 이용자는 초대장을 만드는 호스트와 초대장을 받고 참석 여부를 제출하는 게스트다. 둘 다 로그인 없이 링크로 이용한다.

## 2. 기술스택(변경금지)

프로젝트 초기화 설정과 `package.json`을 기준으로 아래 기술을 유지한다.

| 항목 | 고정 기술 및 설정 |
| --- | --- |
| 프레임워크 | Next.js 16, App Router |
| UI | React 19 |
| 언어 | TypeScript 5, strict 모드 |
| 스타일 | Tailwind CSS v4 |
| CSS 처리 | PostCSS, `@tailwindcss/postcss` |
| 코드 검사 | ESLint, `eslint-config-next` |
| 패키지 관리 | npm |
| 코드 위치 | `src/` 디렉터리 |
| 경로 별칭 | `@/*` → `src/*` |

- 사용자 요청 없이 기술스택이나 메이저 버전을 변경하지 않는다. TypeScript 6 이상이나 Tailwind CSS v3 방식으로 바꾸지 않는다.
- Tailwind CSS는 `src/app/globals.css`의 `@import "tailwindcss"`와 CSS 기반 테마 설정을 사용한다.
- 기존 패키지로 해결할 수 있는지 먼저 확인한다. 새 라이브러리, DB, 외부 서비스를 도입해야 하면 이유를 설명하고 사용자에게 질문한다.
- 데이터 저장 방식과 DB는 아직 정해지지 않았다. 실제 공유와 응답 수집에 사용할 저장 방식을 구현 전에 확인한다.

## 3. 디자인 규칙

- 최종 디자인은 추후 사용자가 제공하는 Figma 디자인을 Figma MCP로 읽어 구현한다.
- 사용자가 지정한 파일과 프레임을 기준으로 레이아웃, 색상, 글꼴, 간격, 이미지와 컴포넌트를 확인한다.
- 아직 최종 디자인 링크가 지정되지 않았다. 이전에 확인한 교육용 슬라이드를 서비스 디자인으로 간주하지 않는다.
- 디자인이 없거나 MCP로 읽히지 않거나 상태별 화면이 빠져 있으면 사용자에게 질문한다. 임의의 디자인을 확정하지 않는다.
- 모바일 화면을 우선한다. 다른 화면 크기의 배치가 불명확하면 확인 후 구현한다.
- 반복되는 UI는 재사용하고, 스타일은 Tailwind CSS v4와 공통 테마를 활용한다.
- 입력 필드의 라벨, 키보드 조작, 읽을 수 있는 대비, 오류·완료 안내 등 기본 접근성을 지킨다. 디자인과 충돌하면 사용자에게 설명하고 확인한다.

## 4. 서비스 구조

서비스 요구사항의 기준 문서는 `docs/prd.md`다. 이 지침이나 사용자 요청과 충돌하거나 의미가 불명확하면 질문한다.

### 목적과 흐름

- 정보를 입력해 5분 안에 모바일 웹 초대장을 만들고, 링크로 공유해 참석 여부를 받는 서비스다.
- 호스트: 만들기 → 미리보기 → 발행 → 링크 공유 → 응답 확인.
- 게스트: 초대장 보기 → 참석 응답 제출 → 완료 안내.

### 화면과 경로

| 경로 | 역할과 기능 | App Router 파일 |
| --- | --- | --- |
| `/create` | 제목·일시·장소·본문 입력, 실시간 미리보기, 발행 후 초대장·응답 현황 링크 표시 및 복사 | `src/app/create/page.tsx` |
| `/i/[id]` | 초대장 보기, 이름·참석 여부·동반 인원 입력 및 제출, 완료 안내 | `src/app/i/[id]/page.tsx` |
| `/i/[id]/responses` | 호스트 응답 목록, 참석·불참 수, 참석 인원 합계 확인 | `src/app/i/[id]/responses/page.tsx` |

위 경로는 구현 목표이며, 현재 모두 구현되었다는 의미는 아니다. `/`의 역할은 PRD에 없으므로 변경 전에 확인한다.

### MVP 범위

1. 만들기 폼과 실시간 미리보기.
2. 추측하기 어려운 고유 ID로 발행하고 링크를 복사하는 기능.
3. 장소 주소를 글자로 표시하는 기능.
4. 게스트 참석 응답과 제출 완료 안내.
5. 호스트 응답 목록과 집계 확인.

- 로그인, 결제, 네이티브 앱, 드래그 편집, 축의금 송금, AI 생성, 다국어는 제외한다.
- 지도나 추가 기능을 임의로 넣지 않는다.
- 공통 레이아웃은 `src/app/layout.tsx`, 전역 스타일은 `src/app/globals.css`에 둔다. 공통 컴포넌트와 데이터 처리 코드는 필요할 때 분리하며 불필요한 구조를 미리 만들지 않는다.

### 구현 전 질문할 미정 사항

- 초대장과 응답을 저장할 DB 또는 서비스, 배포 환경.
- 호스트 응답 현황 링크의 보호 방식. 별도 비밀 관리 키 사용 여부는 사용자 확인 전까지 미정이다.
- 참석·불참 수가 응답 건수인지 인원수인지, 참석 인원 합계에 본인과 동반 인원을 어떻게 포함할지.
- 중복 응답과 응답 수정 허용 여부, 동반 인원의 범위와 불참 시 처리.
- 필수 입력값과 길이 제한, 행사 일시의 시간대, 잘못되거나 만료된 링크의 처리.
- 초대장 수정·삭제, 보관 기간, `/` 화면의 동작 등 PRD에 없는 정책.

미정 사항은 해당 기능을 구현하기 전에 질문한다. 정해지지 않은 정책을 확정된 요구사항처럼 기록하지 않는다.

## 5. 안전규칙

- 기존 파일과 사용자 작업을 먼저 확인한다. 요청과 무관한 수정, 대량 삭제, 설정 초기화를 하지 않는다.
- 데이터 삭제, 덮어쓰기, 되돌리기 어려운 변경, 유료 서비스 사용, 외부 배포는 사용자가 허용한 범위를 확인하고 진행한다.
- API 키, DB 비밀번호, 호스트 비밀 관리 키 등 민감한 값은 코드·저장소·로그에 노출하지 않는다. 서버 비밀값을 `NEXT_PUBLIC_` 환경 변수에 넣지 않는다.
- 게스트 이름과 응답은 필요한 범위에서만 다룬다. 호스트 접근 보호 정책이 정해지기 전에는 응답 목록을 누구나 볼 수 있게 공개하지 않는다.
- 초대장 ID는 순번 대신 충분히 예측하기 어려운 값으로 생성한다. 초대장 ID 자체를 호스트 권한 증명으로 간주하지 않는다.
- 입력값은 서버에서도 검증한다. 사용자 입력을 실행 가능한 코드나 HTML로 직접 삽입하지 않는다.
- 저장·발행·응답 제출이 실패하면 성공으로 표시하지 않는다. 사용자에게 오류와 재시도 방법을 알려준다.
- 임시 데이터나 브라우저 저장소만 쓰는 시제품을 여러 사람이 공유할 수 있는 완성 기능이라고 설명하지 않는다.
- 코드 변경 후 관련 범위에서 `npm run lint`, `npm run typecheck`, `npm run build` 등 적절한 검사를 수행한다. 실행하지 못한 검사와 실패 원인은 명확히 알린다.
- 불확실한 요구사항, 보안 정책, 오류 원인을 아는 것처럼 단정하지 않는다. **모르거나 애매하면 사용자에게 질문한다.**
