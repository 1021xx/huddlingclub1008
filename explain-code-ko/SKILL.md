# 한국어 코드 설명 주석

## 적용 범위

- 이 스킬이 들어 있는 프로젝트에만 적용한다. 프로젝트 루트는 이 스킬 폴더의 상위 디렉터리다.
- 사용자가 지정한 코드 파일에 설명 주석을 추가한다. 코드의 동작, 타입, 변수명, 화면 문구, 스타일, 의존성은 변경하지 않는다.
- 독자는 코딩 초보자다. 줄마다 설명하는 대신 함수, 컴포넌트, 데이터 변환, 조건 분기, 비동기 처리, 주요 화면 영역 등 의미 있는 처리 단위로 설명한다.

## 작업 절차

1. 프로젝트의 `agent.md`와 적용되는 `AGENTS.md`가 있으면 읽는다. 사용자가 준 상대 경로는 프로젝트 루트 기준으로 확인한다. 절대 경로도 실제 파일이 이 프로젝트 안에 있을 때만 사용한다. 프로젝트 밖을 가리키는 심볼릭 링크는 수정하지 않는다.
2. 경로가 없거나 여러 파일로 해석되면 대상 파일을 질문한다. 디렉터리만 지정되면 수정할 파일 범위를 확인한다. 생성 파일, 의존성, 빌드 산출물을 지정했다면 원본 코드 경로를 확인한다.
3. 대상 파일 전체와 기존 주석을 읽는다. 설명에 필요한 경우 관련 타입과 호출부, 가져온 함수의 정의를 추가로 읽되, 관련 파일까지 수정하지 않는다.
4. 코드로 확인되는 동작을 바탕으로 설명한다. **기능의 목적, 서비스 정책, 외부 함수의 동작 등 모르거나 애매한 내용은 임의로 넣지 말고 사용자에게 질문한다.** 답변이 필요한 부분은 보류한다. 명확한 독립적인 부분은 진행할 수 있다.
5. 언어와 문맥에 맞는 주석 문법으로 원본 파일에 추가한다. JSON처럼 주석을 허용하지 않는 형식이면 임의로 형식을 바꾸지 말고 별도 설명 문서 등 대안을 사용자에게 질문한다.
6. 변경 전후를 비교해 설명 주석 외의 코드가 바뀌지 않았는지 확인한다. Git이 없으면 작업 전 내용을 기준으로 비교한다. 사용자가 이미 수정한 내용은 보존한다.
7. 필요한 범위의 기존 린트·타입 검사로 문법이 깨지지 않았는지 확인한다. 검증을 위해 패키지를 새로 설치하거나 설정을 바꾸지 않는다. 검사를 실행하지 못하면 이유를 알린다.

## 주석 작성 기준

- 주요 처리 바로 위에 쉬운 한국어로 짧게 설명한다. 필요하면 입력값 → 처리 → 결과의 흐름과 코드에서 확인되는 이유를 함께 적는다.
- 전문 용어는 처음 나올 때 뜻을 풀어 쓴다. 예: “상태(state)는 화면이 기억하고 있는 값입니다.”
- 자명한 선언이나 문장을 모두 설명하지 않는다. 파일의 전체 역할 설명은 이해에 도움이 될 때만 추가한다.
- 기존 설명이 충분하면 중복 주석을 추가하지 않는다. 다시 실행해도 같은 설명이 쌓이지 않도록 한다.
- 코드에서 드러나지 않는 개발자의 의도나 아직 구현되지 않은 기능을 사실처럼 설명하지 않는다.
- TS/JS에서는 `//` 또는 `/* ... */`, JSX 내부에서는 `{/* ... */}`, CSS에서는 `/* ... */` 등 유효한 문법을 사용한다. 문자열이나 템플릿 리터럴 안에 주석을 삽입하지 않는다.
- `use client`, `use server`, shebang, 타입 참조, 라이선스, ESLint·TypeScript·번들러 지시 주석과 의미 있는 줄바꿈을 보존한다. 설명을 위해 검사 무시 지시문을 추가하지 않는다.
- 버그를 발견하면 별도로 알린다. 주석 작업에 섞어 코드를 고치지 않는다.

## 완료 보고

수정한 파일 링크, 설명을 보강한 주요 처리, 검증 결과와 미해결 질문을 한국어로 간단히 알려준다. 수정할 필요가 없었던 경우도 명확히 알린다.

## 사용 예시

`explain-code-ko/SKILL.md 스킬을 사용해서 src/app/page.tsx에 주요 처리 단위로 한국어 설명 주석을 달아줘.`
